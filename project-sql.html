SQL Basics: Querying a Retail Sales Dataset

My first real SQL project. I grabbed a public retail dataset and started writing queries from scratch — finding top-selling products, calculating total revenue by month, filtering out returned orders. Nothing fancy, but I learned a ton about JOINs and GROUP BY just by playing around with real data rather than textbook examples.

MySQL SELECT JOINs GROUP BY WHERE / HAVING Aggregate Functions Beginner Level
📋 What this project is: An educational exercise using a publicly available retail sales dataset (sourced from Kaggle). I set up a local MySQL database, imported the CSV data, and worked through a series of progressively harder queries — each one teaching me something new. The queries below are real ones I wrote and ran myself.

Query 1 — Total Revenue by Month

The first thing I wanted to know: how does revenue trend over time? This taught me DATE_FORMAT and basic aggregation.

SQL revenue_by_month.sql 
-- Total revenue grouped by month
-- Goal: spot seasonal trends in sales performance

SELECT
    DATE_FORMAT(order_date, '%Y-%m') AS month,
    COUNT(order_id)              AS total_orders,
    ROUND(SUM(sale_price), 2)    AS total_revenue,
    ROUND(AVG(sale_price), 2)    AS avg_order_value
FROM orders
WHERE status != 'Returned'
GROUP BY month
ORDER BY month ASC;

Query 2 — Top 10 Best-Selling Products

I wanted to find which products drove the most revenue. This is where I first used JOIN to combine two tables.

SQL top_products.sql 
-- Top 10 products by total revenue (excluding returns)

SELECT
    p.product_name,
    p.category,
    COUNT(o.order_id)           AS units_sold,
    ROUND(SUM(o.sale_price), 2) AS total_revenue
FROM orders o
JOIN products p ON o.product_id = p.product_id
WHERE o.status != 'Returned'
GROUP BY p.product_name, p.category
ORDER BY total_revenue DESC
LIMIT 10;

Query 3 — Categories with High Return Rates

This one used HAVING to filter after aggregation — a distinction I kept getting confused with WHERE.

SQL return_rates.sql 
-- Find product categories where return rate > 15%
-- WHERE filters rows; HAVING filters groups — learned this the hard way

SELECT
    p.category,
    COUNT(o.order_id)                         AS total_orders,
    SUM(CASE WHEN o.status = 'Returned'
             THEN 1 ELSE 0 END)              AS returns,
    ROUND(
        SUM(CASE WHEN o.status = 'Returned'
                 THEN 1 ELSE 0 END) * 100.0
        / COUNT(o.order_id), 2
    )                                             AS return_rate_pct
FROM orders o
JOIN products p ON o.product_id = p.product_id
GROUP BY p.category
HAVING return_rate_pct > 15
ORDER BY return_rate_pct DESC;

What I Learned

🔗
JOIN is not scary
I kept avoiding JOINs thinking they were complex. Turns out they're just matching rows on a shared column. Writing them on real data made it click immediately.
📌
WHERE vs HAVING
WHERE filters before grouping; HAVING filters after. I wrote about 6 broken queries before I actually understood why this distinction exists.
📐
ROUND() everything
Without ROUND(), currency values come back as $48204.498372. Learned to always wrap monetary calculations and to specify decimal places.
🚫
Filter bad data first
Including returned orders skewed every revenue calculation. Filtering with WHERE status != 'Returned' was a game-changer for accuracy.
