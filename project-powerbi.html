Dashboard in Power BI

My first real Power BI project. I built a dashboard that tracks daily case volume, SLA compliance, and CSAT scores for a fictional support team. The data is made up, but the metrics are pulled straight from what I track every day at Concentrix.

Power BI Desktop DAX KPI Cards Slicers Data Modeling
Why this project? I wanted to take the numbers I already knew from my job and build something a manager could actually open and get answers from in under a minute. KPI cards, trend lines, a slicer for date range. Simple, but real. Learning DAX was harder than I expected — it looks like Excel formulas but behaves very differently.

Step 1 — Data Model

The report uses two tables: Cases and a Date table. The Date table is essential in Power BI — without it, time intelligence functions like DATEADD and SAMEPERIODLASTYEAR will not work properly. This was the first thing that tripped me up.

DAX Date Table (calculated) 
-- Create a Date table so time intelligence works correctly
-- Go to: Modeling > New Table, then paste this

DateTable =
CALENDAR(
    DATE(2024, 1, 1),
    DATE(2024, 12, 31)
)

-- Then add these calculated columns to the DateTable:

Year   = YEAR([Date])
Month  = MONTH([Date])
MonthName = FORMAT([Date], "MMMM")
Quarter = "Q" & QUARTER([Date])

Step 2 — Core DAX Measures

DAX is the formula language inside Power BI. These are the four main measures I built. I created them all inside a dedicated Measures table to keep things organized.

DAX Measures Measures Table
Total Cases — count of all rows in the Cases table
Total Cases = COUNTROWS(Cases)
Simple starting point. COUNTROWS counts every row in the table, regardless of any filter. Once you connect a slicer, Power BI automatically filters this for you.
CSAT Score — average satisfaction rating, formatted as %
CSAT Score = DIVIDE( CALCULATE(COUNTROWS(Cases), Cases[csat_rating] >= 4), COUNTROWS(Cases), 0 )
DIVIDE is safer than using "/" because it handles division by zero automatically. Cases with a rating of 4 or 5 out of 5 count as satisfied. The third argument (0) is what shows if there is no data.
SLA Compliance — % of cases resolved within the required time
SLA Compliance = DIVIDE( CALCULATE(COUNTROWS(Cases), Cases[met_sla] = "Yes"), COUNTROWS(Cases), 0 )
CALCULATE with a filter is the core of DAX. It recalculates COUNTROWS but only for rows where met_sla equals "Yes". Everything else works the same way.
MoM Case Change — how case volume shifted versus last month
Cases Last Month = CALCULATE( COUNTROWS(Cases), DATEADD(DateTable[Date], -1, MONTH) ) MoM Change % = DIVIDE( [Total Cases] - [Cases Last Month], [Cases Last Month], 0 )
DATEADD shifts the filter context back by one month. This is why the Date table is so important — without it, DATEADD simply does not work. I learned this the frustrating way.

What I Learned

📅
Always build a Date table first
I spent two hours wondering why DATEADD was not working. The answer was always the same — no proper Date table. Now it is the first thing I create in any Power BI file.
⚙️
CALCULATE is the heart of DAX
Almost every useful measure uses CALCULATE. It changes the filter context, which is what makes DAX so powerful. Understanding filter context was the biggest learning moment in this project.
➗
Always use DIVIDE, not "/"
Using "/" crashes the visual if the denominator is zero. DIVIDE handles it cleanly and lets you set a fallback value. Small habit, saves a lot of broken KPI cards.
🎛️
Slicers make dashboards interactive
Connecting slicers to visuals was the moment this stopped feeling like a static table and started feeling like an actual dashboard. Filtering by month, by case type — it all updates instantly.
